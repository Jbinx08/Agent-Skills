# Vibe Drive Project System

## 1. 목적

이 규칙은 AI Agent가 Google Drive를 이용하여 현재 작업 중인 프로젝트를 ZIP으로 저장하고, 필요할 때 다시 불러와 작업을 이어갈 수 있도록 하기 위한 규칙이다.

로컬 PC의 프로젝트 저장 위치는 고정하지 않는다.

Google Drive는 프로젝트의 **저장 및 불러오기 용도**로 사용한다.

---

# 2. Google Drive 구조

Google Drive에는 다음 폴더를 사용한다.

```text
VibeProjects/
├── ProjectA.zip
├── ProjectB.zip
└── ProjectC.zip
```

---

# 3. 프로젝트 저장

사용자가 다음과 같이 저장 의사를 표현하면 프로젝트 저장 작업을 수행한다.

```text
"프로젝트 저장해"
"Drive에 저장해"
"여기까지 저장해"
"이거 저장해"
"Jskill 저장해"
"백업해"
```

문장이 정확히 일치하지 않아도 사용자의 의도가 **현재 프로젝트를 Google Drive에 저장하는 것**이라면 동일하게 처리한다.

## 저장 절차

1. 현재 AI Agent가 작업하고 있는 프로젝트의 루트 폴더를 확인한다.
2. 프로젝트 이름을 확인한다.
3. 프로젝트 전체를 ZIP으로 압축한다.
4. Google Drive의 `VibeProjects` 폴더에 `<프로젝트명>.zip`으로 업로드한다.
5. 동일한 프로젝트가 이미 저장되어 있다면 기존 저장본을 최신 버전으로 업데이트한다.
6. 업로드가 실제로 성공했는지 확인한다.
7. 성공 여부를 사용자에게 알린다.

Google Drive 업로드 성공을 확인하기 전에는 저장이 완료되었다고 말하지 않는다.

---

# 4. 프로젝트 불러오기

사용자가 다음과 같이 프로젝트를 불러오려는 의사를 표현하면 불러오기 작업을 수행한다.

```text
"Jskill 불러와"
"Jskill 프로젝트 불러와"
"Jskill 이어서 하자"
"Drive에서 Jskill 가져와"
"Jskill 작업 계속하자"
```

문장이 정확히 일치하지 않아도 사용자의 의도가 **Google Drive에 저장된 프로젝트를 불러오는 것**이라면 동일하게 처리한다.

## 불러오기 절차

1. Google Drive의 `VibeProjects` 폴더를 확인한다.
2. `<프로젝트명>.zip`을 찾는다.
3. ZIP 파일을 다운로드한다.
4. 사용자가 지정한 위치가 있다면 해당 위치에 압축을 해제한다.
5. 위치가 지정되지 않았다면 현재 작업 환경에서 적절한 위치를 사용한다.
6. 동일한 이름의 기존 프로젝트가 있어 덮어쓰기 위험이 있다면 임의로 덮어쓰지 않는다.
7. 압축 해제 후 프로젝트의 주요 파일과 구조를 확인한다.
8. 필요한 개발 환경과 의존성을 확인한다.
9. 필요한 의존성이 없다면 프로젝트의 설정 파일을 기준으로 복원한다.
10. 프로젝트 작업을 이어갈 수 있는 상태로 준비한다.

---

# 5. ZIP 제외 규칙

인터넷에서 다시 다운로드하거나 자동으로 재생성할 수 있는 대용량 의존성 및 캐시는 기본적으로 ZIP에서 제외할 수 있다.

대표적인 예:

```text
node_modules/
.next/
.gradle/
__pycache__/
.cache/
tmp/
temp/
```

단, 프로젝트를 복원하는 데 필요한 원본 파일이나 설정 파일은 제외하지 않는다.

---

# 6. 빌드 결과물

다음과 같은 사용자가 직접 사용할 수 있는 최종 결과물은 단순 캐시로 취급하지 않는다.

```text
*.exe
*.msi
*.apk
*.aab
```

`build/`, `dist/` 등의 폴더에 최종 결과물이 존재할 수 있으므로 해당 폴더를 무조건 제외하지 않는다.

최종 결과물인지 단순 재생성 가능한 빌드 캐시인지 판단하여 처리한다.

---

# 7. 민감한 파일

다음과 같은 파일에는 API Key, 인증 토큰, 비밀번호 등의 민감한 정보가 존재할 수 있다.

```text
.env
.env.local
credentials.json
token.json
*.pem
*.key
```

민감한 정보가 포함된 파일은 임의로 Google Drive에 업로드하지 않는다.

프로젝트 실행에 반드시 필요한 경우 안전한 저장 방법을 사용하거나 사용자에게 확인한다.

---

# 8. 의존성 복원

프로젝트를 불러왔을 때 제외된 라이브러리나 의존성이 있다면 프로젝트에 기록된 정보를 기준으로 복원한다.

### Node.js

`package-lock.json`이 존재하면 일반적으로 다음을 사용한다.

```bash
npm ci
```

프로젝트 상황에 따라:

```bash
npm install
```

### Python

`requirements.txt`, `pyproject.toml` 등 프로젝트에서 실제 사용하는 의존성 관리 방식을 확인한다.

### Gradle

Gradle Wrapper 및 프로젝트 설정을 기준으로 필요한 의존성을 다시 다운로드한다.

라이브러리 버전을 임의로 추측하지 않는다.

---

# 9. 핵심 원칙

- 로컬 프로젝트 경로를 특정 위치로 강제하지 않는다.
- 현재 AI Agent가 작업 중인 프로젝트를 저장 대상으로 사용한다.
- Google Drive의 `VibeProjects`를 프로젝트 저장소로 사용한다.
- 사용자의 자연어 의도를 인식하여 저장 또는 불러오기 작업을 수행한다.
- Git 또는 GitHub 사용을 요구하지 않는다.
- 저장할 때 프로젝트를 ZIP으로 만든다.
- 불러올 때 ZIP을 다운로드하여 압축 해제한다.
- 재생성 가능한 대용량 파일은 가능한 한 저장하지 않는다.
- 사용자에게 필요한 최종 결과물은 보존한다.
- 민감한 인증정보는 임의로 업로드하지 않는다.
- 기존 로컬 파일을 위험하게 덮어쓰지 않는다.
- Google Drive 업로드 성공 여부를 확인한 후 저장 완료를 보고한다.
